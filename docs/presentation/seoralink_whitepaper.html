Administrative Framework: Ownership & Control

Removing centralized admin discretion while maintaining honest technical distinctions across the stack.

Formal Renunciation Statement

“After deployment and verification, applicable smart-contract ownership/admin privileges are intended to be renounced or permanently restricted so that no individual can arbitrarily modify core business rules, balances, referral logic or payout mechanisms.”

Honest Architectural Disclosures: Smart Contract vs. Off-Chain Stack

SEORALINK upholds strict cryptographic truth. Renouncing smart contract ownership does NOT imply the entire ecosystem is magically decentralized across every layer. We clearly distinguish between operational tiers:

• Smart Contracts: Autonomous logic deployed to the blockchain. Ownership is renounced/restricted; business math cannot be altered.
• Frontend & Web Hosting: Client-facing domain (seoralink.com) hosted on cloud/CDN infrastructure for fast global access.
• Domain Ownership: Web2 DNS registration is subject to standard registrar conventions and organizational custody.
• Blockchain Governance: The protocol relies on the underlying L1/L2 network consensus for uptime and transaction inclusion.
• Upgradeability & Proxies: Core pool logic is engineered to be immutable; any emergency pause features must use multi-sig timelocks.
• Off-Chain Indexing: Performance caches & subgraph nodes mirror public ledger data to accelerate UI queries.
Immutable Protocol Invariants
  • $10 Entry requirement cannot be inflated or altered arbitrarily.
  • 5% direct affiliate and 5% upgrade allocations are hardcoded.
  • Global single-leg queue sequencing executes without manual sorting.
  • User earned credits remain claimable exclusively by wallet owners.
Privileged Key Restrictions

Timestamp-Based Global Single-Leg Sequence

When participants fulfill rank prerequisites, their transition request is evaluated against the blockchain's block timestamp and transaction sequence. Eligible IDs are placed chronologically into the global pool.

However, blockchain timestamp ordering alone does not magically create decentralization. Equity and trust depend strictly on verifiable, open-source smart-contract algorithms executing deterministically on-chain.

Four Streams of Global Single-Leg Volume
1. Direct Upline Team Stream:
IDs originating from your direct sponsorship line and organizational hierarchy.
2. Upline Overflow (Spillover):
IDs placed by active upline sponsors expanding community membership globally.
3. Crossline Participation:
IDs arriving from independent affiliate teams across different regions and continents.
4. Downline Momentum:
IDs produced by network depth advancing through lower rank tiers simultaneously.
Direct Upline Team Priority Rule
Primary Algorithmic Rule:
“Direct Upline Team receives priority under the defined placement mechanism.”

When multiple eligible IDs contest pool placement within identical timestamp intervals, the smart contract calculates priority based on proximity to the qualifying sponsor line, preserving organizational value while maintaining global pool fluidity.

Public Auditability of Queues
Every queue enqueue, matching event, and rank promotion emits an indexed Solidity event to the blockchain. Anyone can verify the exact sequence order, eliminating preferential treatment or behind-the-scenes manipulation.

Institutional smart-contract design patterns mitigating reentrancy, arithmetic overflow, and state corruption.

Reentrancy & Mutex Protection

Smart contracts implement OpenZeppelin's standard ReentrancyGuard pattern across all external reward claiming functions. State modifications always precede token transfers (Checks-Effects-Interactions pattern).

Arithmetic Overflow Hardening

Developed on Solidity compiler versions ≥ 0.8.20 with native integer overflow/underflow reversion checks, eliminating historical integer wrapping vulnerabilities without runtime gas bloat.
